# 摘要草稿

MCP 存草稿，仓库存定稿。同一份摘要不两头存。

## 工具（9 个）

`search_nodes`、`open_nodes`、`create_entities`、`add_observations`、`create_relations`、`delete_entities`、`delete_observations`、`delete_relations`、`read_graph`（少用）

这个服务没有 `update_*`：要改内容就 `delete_observations` 后 `add_observations`，不要删实体重建。

## observation 用键值

一条 observation = `键: 值`，键固定四个：

| 键 | 内容 | 例 |
|---|---|---|
| `已确认` | 用户同意或已验证的结论 | `已确认: 入口改为 INDEX.md` |
| `推断` | 我的判断，未验证 | `推断: 图谱重建会被静默跳过` |
| `下一步` | 未完成事项 | `下一步: 等首次运行确认` |
| `时` | 年-月-日 | `时: 2026-10-25` |

禁止：

- 把 `推断` 并进 `已确认` 的句子里
- 自造键（`结论`、`要点`、`备注`）
- 一条里塞两个键

## 命名空间（硬约束）

两个记忆服务共用同一套图结构，只靠命名隔离。规则不可破：

| 库 | 实体名 | 类型白名单 | 关系白名单 |
|---|---|---|---|
| Memory（本库） | 必须 `S:` 前缀：`S:2026-10-25 记忆系统重构` | 只有 `summary` | 只有 `caused` `follows` |
| KG Memory（图谱库） | 原名，无前缀：`INDEX.md` | `file` `tool` `project` `person` | 六个动词，见该库技能 |

禁止：

- 本库出现无 `S:` 前缀的实体 → 立即 `delete_entities`
- 本库出现 `file` / `tool` / `project` / `person` 类型（那是图谱库的事）
- 把仓库文件名当实体名写进本库；文件名属于图谱库
- 同一实体在两库各建一份

写入前自检三问：带 `S:` 了吗？类型是 `summary` 吗？名字里有日期和阶段吗？任一答否就不写。

## 存储模型

摘要没有专用接口，用实体表示：

```
name:         S:2026-10-25 记忆系统重构
entityType:   summary
observations: [
  "【已确认】入口改为 INDEX.md，技能从 16KB 降到 3KB",
  "【推断】图谱重建会被静默跳过，未验证",
  "【下一步】等一次真实写入确认提交落在 main"
]
```

- 实体名必须带 `S:` 前缀，与图谱服务隔离
- 一条实体 = 一个阶段，同阶段观察合并成一条实体
- 跨阶段的关系用 `create_relations` 连：`S:2026-10-24 caused S:2026-10-25`

## 何时写

- 会话较长，或任务已跨多个阶段
- 上下文即将被压缩的长对话中段
- 结论里「已确认」与「未确认」混在一起时

不写：普通问答、单轮事实、仓库已有的条目。

## 三种状态必须分开

| 标签 | 含义 |
|---|---|
| 【已确认】 | 用户明确同意，或已验证 |
| 【推断】 | 我的判断，未验证 |
| 【下一步】 | 未完成事项 |

**不许把【推断】并进【已确认】的句子里。** 混写会让草稿在转写时变成假事实。

## 何时读

- 回顾「之前定了什么」→ `search_nodes("S:2026-10")`，取最近 3 条
- 确认某条是否定案 → `open_nodes(["S:日期 阶段名"])`，只看那一条
- 不用 `read_graph`

## 转定稿

任务结束时：

| 内容 | 去哪 | 之后 |
|---|---|---|
| 【已确认】结论、偏好、纠正 | 仓库场景文件 / `LOG.md` | `delete_entities` 对应 S 实体 |
| 【推断】未验证 | 直接丢弃 | — |
| 【下一步】未完成 | 写进 `LOG.md` 或告知用户 | — |

**转写后删掉 MCP 里那条**，避免两处各存一版。

## 寿命

| 层 | 位置 | 跨会话 |
|---|---|---|
| 草稿 | MCP `S:` 实体 | 否 |
| 原文 | `LOG.md` | 是 |

不要让 MCP 承担长期记忆，它跨不过会话。
