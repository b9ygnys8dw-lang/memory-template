# 记忆运维

> 触发：要记东西、要改条目、要标作废、找不到某条、不知道该写哪。

## 原则

- **好的留下，坏的扔掉。** "坏"由用户判定，我只提议，不自行裁决
- **"扔掉" = 标 `作废`**，不物理删除。原文保留，只是不再参与判断
- **同一主题多条时，以日期最新的为准**；旧的自动失效，不删、不改
- **不设条数上限，不设行数上限**

## 条目格式

- 画像条目：`- YYYY-MM-DD 一句话`（保留原话）
- 日记条目：见 `knowledge/writing.md`，本文件不重复

## 情绪

- 不确定的情绪由模型自行判断，不建规则
- 推断必须标"（推断）"，且只影响当轮回应，不写入长期结论
- 用户明示的情绪（"这很烦""这条不错"）写进对应事件，用自然语言，不加字段

## 检索

- 先想"我会怎么描述这件事"，再用那个词 grep `LOG.md` 的标题
- 命中后只读那一节，不通读全文
- grep 无结果 → 直说"没有记录"，改问用户
- **排除作废**：`grep 关键词 LOG.md | grep -v 作废`，旧条目不与现行条目争线索
- **命中即记**：该条真的影响了判断 → `HITS.md` 追加一行 `YYYY-MM-DD 条目名`；只是读到不影响判断的不记

## 写入

- 一条一事，保留原话；不概括用户的措辞
- 结论写仓库；未验证的写 MCP 草稿并标"未定稿"
- 写完引述原文，不报数量
- **写入走 git 工作副本**：`gh auth setup-git`（一次性）→ `gh repo clone` 到 `/workspace/memory-repo` → 改文件 → `wc -c` 校验 → `git add -A && git commit && git pull --rebase && git push`
- 不用 Contents API 逐文件写（读改写会丢更新，且 sha 与内容易不同源）
- commit 前 `wc -c` 校验非空；空文件不许提交
- 提交后确认落在 `main`；非 main 就说"仅在分支，未入主分支"

## 清点（`HITS.md` 的消费者）

- 触发：用户说"清点""哪些条没用上"
- 读 `HITS.md` 与 `LOG.md` 标题，列出**从未出现在 HITS 的条目**
- 只提议"这条要不要标作废"，判定权在用户
- 一次最多列 10 条，最旧的优先

## 不做什么

- 不压缩、不降档、不归档、不算权重
- 不删任何条目，包括"看起来没用"的
- 不推测日期；时间只在会话开始与写记忆文件前查
