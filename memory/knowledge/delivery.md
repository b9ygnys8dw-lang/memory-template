# 交付

> 触发：要给用户一份文件、导出格式、或更新旧交付物。

## 命名规范（强制）

- 交付名必须带版本或日期：`<包名>-v<N>.zip`、`<名>-YYYY-MM-DD.md`
- **不留无版本名**：`mcp-graph-memory.zip` 这种名字一律不用，否则会拿到旧版
- 上一版直接删，不与新版并存；多版本并存等于让人猜
- 单文件同步规则：包内 `SKILL.md` 不改名，但在包外另给一份 `-SKILL-vN.md`
- 交付前 `ls` 一遍，确认没有同名旧件

## 偏好

- 交付物：Word/PDF、表格、md 手册；倾向要文件，不要只在对话里给
  `触发: 导出、格式、下载`
- 更新已交付过的文件必须换名
  `触发: 第二轮交付、同名、旧缓存`
- 一个大包 + 一个单文件版：有的入口只能单文件上传
  `触发: 上传技能、导入`

## A1 交付脚本

1. 文件名带版本或日期，不复用旧名
2. 校验：行数、关键词、总大小是否合理
3. 给链接，一行说明“改了什么”
4. 多文件时给压缩包，另附单文件版
5. 删除旧版后确认目录里无旧名

完成信号：链接可打开，内容与说明一致，目录里不存在同名旧件。
失败处理：用户说拿到旧的 → 立即换新名重发；记为 C2 类。

## 案例 C2 拿旧文件当新版交付

- 触发：更新已交付过的文件
- 错法：同名覆盖后直接给链接
- 原因：交付容器对同名文件可能返回旧缓存
- 正解：一律改名；上一版删掉；给链接前核对大小
