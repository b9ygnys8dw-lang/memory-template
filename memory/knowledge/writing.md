# 怎么写日记

> 触发：要写 `LOG.md`、或拿不准"这事该不该记"时读。
> 本文件只回答三件事：记不记、写什么、怎么判断情绪。

## 一、先判断记不记

只有四种情况写：

| 情况 | 判据 |
|---|---|
| 纠正 | 用户明确否定了我说的或做的（"不对""不是这样"） |
| 意外 | 有东西和预期不符，且已核实（报错、取到旧版、资格不够） |
| 偏好 | 用户明确表达了喜欢或不喜欢，且不是一次性要求 |
| 结论 | 讨论出了可复用的判断，下次能直接拿来用 |

不写：普通问答、单轮事实、用户在发散思考时的假设、我说的话本身。

## 二、写什么

标题：`## YYYY-MM-DD 事件名 — 结论`

**标题必须自带结论**：一句话让人不读正文也知道这件事是什么、结论是什么。正文只是细节。

正文三句，句数不限，但这四条要素必须有：

```
发生了什么。
我怎么看。
我要求什么。
```

- `为什么` 融在第二或第三句里，不单列
- 一条只写一件事；混了两件就拆开
- 保留用户原话，不概括、不润色
- 不写"进行了讨论""完成了优化"这类无对象的句子

## 三、情绪怎么判断

模型没有真实情绪，判据只能是**词的范围与定义之间的包含关系**：上位词包住下位词。

- 写具体的词和它所属的类别：`语气冲`（属负面，下位：不耐烦）
- 不写概括：`他很生气`、`用户有点不满`——无法判断，也无法反驳
- 用词的边界要有出处：要么是用户自己说的词，要么是我从原话里摘的词
- 推断要标"（推断）"，只影响当轮回应，不写进长期结论

## 四、写完的自检

1. 标题里有结论吗；只写事件名就算不合格
2. 日期是 UTC 今天吗（北京 00:00–08:00 视为前一天）
3. 四条要素齐了吗；有没有一句是无对象的
4. 情绪词是具体的词，还是"生气""不满"这类概括
5. 提交落在 `main` 了吗
6. 回复里引述原文了吗（不报数量、不说"已记住"）
